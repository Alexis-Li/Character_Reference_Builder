# Domain Docs

采用 **single-context**：根目录 `CONTEXT.md` 维护统一领域词汇，`docs/adr/` 按需维护架构决策。当前没有多包或多上下文布局。

## 阅读顺序

1. 探索相关任务前，先阅读根目录 `CONTEXT.md`。
2. 如 `docs/adr/` 存在，只读取与当前任务有关的 ADR。
3. 需要核对产品设想时，通过 `docs/README.md` 定位需求草案，区分草案提议与已确认要求。

如果领域文档或 ADR 尚不存在，直接继续，不将缺失作为阻塞，也不为了占位创建文档。

## 消费规则

- Issue、规格、测试及设计讨论采用 `CONTEXT.md` 的术语，避免使用其明确排除的同义词。
- 遇到未收录概念时先确认是否属于既有概念；真实词汇缺口交给 `domain-modeling` 在澄清后更新。
- `CONTEXT.md` 只写领域词汇，不放任务清单、实现细节或技术选型。
- 若提议与既有 ADR 冲突，明确指出冲突的 ADR 和重新讨论的理由，不默默覆盖。
- 只有实际作出重要且有取舍的架构决策后才新增 ADR；目录约定本身不要求编造决策。
