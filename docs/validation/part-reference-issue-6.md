# CRB-05 单部件界面验证

实现入口为首页“单部件参考工作区”。关闭首次引导／欢迎弹层后打开；图像模型沿用项目已有默认设置，也可在生成节点上调整。

## 已交付路径

- 导入一张或多张原画，以文字说明部件、左右、归属和排除对象，确认或更正目标后生成；不要求 SAM、Mask 或预先拆件。
- 加载默认单部件预设仅填写要求，不发请求。共同锁定和部件有效要求独立保存，每次生成及节点重跑都读取当前有效约束。
- 每次只生成指定的正面、侧面或背面，其他视图的人工选定版本作为一致性参考，保持原文件。优化输入可以是未批准候选。
- 候选并排显示，可独立选中、批准、打开大图、下载旧版本和创建分支。批准后再选中不清除批准状态。
- 优化链继承前轮修改要求；从旧候选分支只继承该分支的要求。长期变更可写入部件有效要求，更正历史按部件隔离。
- 云端失败保留候选和人工选择。所有无资料支持的遮挡补全均提示为推测，等待人工核对。

## 本地验证（2026-09-12）

最终 `npm run build` 通过；最终全量 `npm run test:run` 通过 133 个文件、2718 项。另对执行器、候选选择、领域契约及新增工作区执行了 53 项定向回归，全部通过。

独立 `npx tsc --noEmit` 仍报告仓库已有测试夹具类型问题（包括缺少执行上下文字段和测试 Mock 类型），不作为通过证据；生产构建的类型检查通过。

真实 Edge 浏览器交互验证：载入预设零请求 → 导入资料 → 确认目标 → 保存共同锁定 → 正面生成与选定 → 背面生成 → 未批准候选连续优化两轮 → 从旧候选发起失败分支 → 批准并选中旧候选 → 下载正面旧结果。检查 5 次请求的参考图数量分别为 1、2、3、3、3；连续优化请求包含共同锁定和此前两轮要求。截图已检查，失败时四个历史候选仍可访问。

可复跑脚本：`scripts/validation/part-reference-ui.cjs`。先启动本机服务，设置外置 `CRB_TEMP_ROOT`，通过 `NODE_PATH` 提供临时安装的 `playwright` 包，运行 `node scripts/validation/part-reference-ui.cjs`；本机需安装 Edge。服务地址可通过 `CRB_BASE_URL` 指定，默认 `http://127.0.0.1:3210`。脚本拦截生成请求，使用测试图片，无真实付费生成。
