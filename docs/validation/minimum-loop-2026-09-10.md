本文记录 CRB-01 导入前的候选评估；现役原型状态见 [CRB-01 基线](../crb-01-baseline.md)。原始快照和可清理证据已迁到 `CRB_TEMP_ROOT/validation/`。

2026-10-21 的真实 Q01 增量见第 7 节；第 1–6 节保留 2026-09-10 的候选评估与执行协议，不作为当前任务状态快照。完整任务范围及剩余验收以 [Issue #8](https://github.com/Alexis-Li/Character_Reference_Builder/issues/8) 为准。

2026-10-22 用户确认现有选定结果可用，取消人工计时和量化费用门槛；费用／额度保留未知，当前有效口径见第 11 节。第 4 节协议按这一明确决定修订，旧要求可从[修订前固定版本](https://github.com/Alexis-Li/Character_Reference_Builder/blob/08c4f8fc26e495674ed7038bab91fe80827005ad/docs/validation/minimum-loop-2026-09-10.md#4-真实模型验证执行协议)恢复。其他历史实测观察保持原样。

**结论：工程可行性已有实测证据，可以启动受控原型开发；完整生产闭环尚未验收通过。** Node Banana 可作为二次开发起点，但多参考传递、候选选择和失败回退必须修改。真实角色质量、账户可用性及总成本尚未验证，不以模拟出图或构建成功代替。

## 1. 验证目标与边界

最小路径：**导入原画 → 框选／文字指定部件 → 首次参考生成 → 指定修改 → 比较并人工选择 → 保存重开 → 导出。**

先验证单个部件，不要求先搭完整拆件、A-pose 或角色三视图链。不在本轮扩展视频、3D 生成、无人值守批处理和 SAM；SAM 是独立可选能力。

分开记录三个层次：

1. 工程行为：输入传递、版本保留、失败处理、文件落盘与重开。
2. 云端能力：实际账号接受请求、参考利用、编辑效果和费用。
3. 美术可用性：模型师是否接受参考用于建模，推测是否清楚且可纠正。

当前完成第一层的候选评估；第二、三层缺少用户指定的真实原画、可调用 Provider 和费用范围。已请求这些信息，本轮未收到。进程环境中的 `OPENAI_API_KEY`、`GEMINI_API_KEY`、`GOOGLE_API_KEY` 均未配置；没有扫描或读取其他应用私有凭据，也没有把 Codex 内置生成能力当成独立产品接口。

### 3.2 失败的原因与影响

- **多参考丢失：** OpenAI handler 明确取 `input.images[0]`。前端能接多张图不代表端到端支持多参考；必须修正适配器并测试请求形态。[源码](https://github.com/shrimbly/node-banana/blob/5c0e0ae6150f29a6de819f8d6f1dedba15151f7c/src/app/api/generate/providers/openai.ts#L62)
- **回退过宽：** 除 abort 和相同模型外，一般错误都会尝试备用，辅助函数没有预算或“上游是否执行”判定；切换时还清空输出。[源码](https://github.com/shrimbly/node-banana/blob/5c0e0ae6150f29a6de819f8d6f1dedba15151f7c/src/store/execution/runWithFallback.ts#L54)
- **保存测试跨平台问题：** 路由测试使用 `/test/dir`、`/etc` 等路径；Windows 上 `path.resolve(input) !== input` 导致提前失败。真实原生绝对路径读写通过，但 `E:/…` 形式实测被同一判断误拒绝。应修复合法路径归一化并保留真正的越界拒绝。[校验源码](https://github.com/shrimbly/node-banana/blob/5c0e0ae6150f29a6de819f8d6f1dedba15151f7c/src/utils/pathValidation.ts#L23)

没有为了让基线通过而修改上游生产代码，也没有把失败测试改成预期成功。重跑探针在当前快照返回非零是如实报告需求缺口。

## 4. 真实模型验证执行协议

待输入齐备后按以下固定样本执行，不能先看结果再修改通过条件。样本清单保存在本地角色项目中，包含输入哈希、目标部件、已有事实、允许推测范围和审核人。

| 样本 | 最小资料 | 首次生成与修改要求 | 重点检查 |
| --- | --- | --- | --- |
| Q01 独立可见部件 | 一张原画，清晰鞋／护甲／腰带 | 文字指定；随后修正一处细节 | 目标归属、数量、轮廓、配色、连接位置 |
| Q02 部件与手重叠 | 一张存在遮挡的原画及框选 | 仅生成指定部件，补全遮挡 | 排除手及邻物；不可见结构标为推测 |
| Q03 已有背面依据 | 同角色正面、背面及非对称细节 | 只优化背面，正面保持原文件 | 确实利用背面依据，左右关系正确，正面哈希不变 |
| Q04 缺失背面 | 与 Q03 对应的正面，故意不提供背面 | 生成必要背面参考 | 不声称知道未提供设计，明确推测；用于与 Q03 对照 |

每个已获准 Provider 对同一资料执行一次首轮生成和至多两轮人工指定优化。这个上限是本次可行性实验的调用上限，不限制产品以后的迭代次数；扩大实验需先更新费用范围。完整矩阵至多为“4 个样本 × 3 次调用 × Provider 数量”，生成张数、输入量和真实价格仍需运行前计算；达到调用或费用任一上限即停止，不静默换 Provider。

先完成一个 Provider 的 Q01，再扩展 Q02–Q04；确认首个组合值得继续后，才验证第二个兼容 Provider 的替换与混用。订阅入口失败应单列，不用 API 成功替代。

逐次记录：资料及版本、目标部件／视图、有效约束、修改范围、实际 Provider／模型／授权类型、应用自动记录的开始结束时间与请求耗时、请求状态、可得 usage／费用、输出文件与哈希、用户差异与可用性判断。费用／额度未提供时标为未知，不要求用户另行取得或量化，不能从缺失 usage 或第三方补零推定免费。

**图像效果通过条件：** 每个样本都能在本轮约定调用／费用范围内获得模型师认为可继续建模的选定参考；已有设计的重大偏差已修正，或被明确记录并由模型师接受。所有输出都有依据、推测和审核状态；局部优化不覆盖保留视图；保存重开可继续优化，导出资产与选定版本一致。若仅部分样本达到图像效果要求，报告适用范围及未达标结论，不宣称全矩阵通过；后续决定换模型或调整方案时，在新授权范围内验证。

工程验收与模型效果分别判断：项目负责完整传递资料、要求与参数，保留候选／选定资产，支持比较和拒绝结果，并遵守调用／费用范围。输入正确而输出细节偏离要求，记录为模型效果限制；只有参考丢失、要求传错、资产误覆盖等实现错误才进入工程缺陷清单。按约定执行并形成有证据的负面结论可以完成相应效果实验，不要求反复付费直到生成成功，也不以单个模型样本未达预期阻塞工程 PR。生产采用与完整任务关闭仍按各自已同意范围判断。

2026-10-22 用户明确取消人工整理计时、人工基线和量化效率对比，不再将它们作为本项验收条件。产品运行耗时应自动记录用户点击运行发起请求至结果返回的端到端时长，包含网络、排队及服务端等待；不让用户用秒表补测，也不反推历史人工操作时间。未取得量化基线时不声称效率提升。服务商未提供的费用／额度维持未知，不要求完整成本或每个合格部件成本数值。

### 质量、保存与恢复

首轮产物包含完整头部和双耳，主要颜色、眼鼻及大致朝向保留，中央下缘毛束偏长。优化后该区域明显缩短，双耳、眼鼻和主要侧颊大体保留。缩短幅度并非精确三分之一，局部毛束、脸部体积、表情和光照仍存在差异。按用户指定的 AI 视觉评审选用优化版，记录为可继续使用的参考；推测、上述差异及未取得模型师判断的限制保留在本地评审和导出侧录中。

首轮保存后复制整个项目目录，从实际 UI 读取副本继续优化。发现并修复两项工程问题：

1. **目录打开只有系统选择器。** 增加“项目目录路径 → 按路径打开项目”，沿用现有受保护路由；失败保留当前项目与输入，重开不发生成请求。
2. **重开图像损坏。** 生成节点的外置保存遗漏输出引用，文本路径清理会把 Base64 中的斜杠当作路径截断；重开缓存了截断文本，导致 OAuth 栅格预检拒绝及保存失败。独立资产文件完整。修复生成图外置引用、栅格数据 URL 的字节保真，以及从独立候选资产恢复旧损坏内嵌输出。没有放宽栅格解码要求，也没有重做首轮云端生成。

修复后从旧副本恢复完整图像，哈希与首轮服务商输出一致；成功优化后，首轮文件哈希保持不变。最终再次从磁盘重开，两个候选、优化父引用、选择与批准状态均保留；导出 PNG 的 SHA-256 与选定候选及本轮服务商输出三方一致。没有额外生成或自动回退。
