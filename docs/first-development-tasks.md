## CRB-01：建立可复现的原型基线与 Windows 启动入口

问题：现在只有隔离评估快照，产品仓库没有可运行应用；上游 Windows 路径测试不通过，用户也不应手工启动多个服务。

范围：按 ADR 导入固定快照，保留原始来源、许可证和锁文件；提供安装、构建、测试与本机启动命令；提供可双击启动／停止的 Windows 入口，绑定回环地址，处理端口占用和重复启动。初始界面只展示最小闭环需要的通用工具与节点。修复合法 Windows 路径归一化和测试夹具，不放宽真正的越界路径检查。

验收：干净安装与生产构建通过；双击后可打开本机页面，重复启动不产生多个后台；关闭／停止行为明确；原生及正斜杠合法路径都可读写；真正的非法路径仍被拒绝。相关上游文件测试在 Windows 通过。记录并保留 P04–P07 已知失败，不把基线导入称为业务验收通过。

交付：可复现应用基线、启动入口、README 操作步骤、基线检查报告。暂不同时升级主框架或引入桌面壳。

## CRB-02：角色项目、资产版本及人工选定结果

问题：上游当前输出会随重跑替换，备用失败可清空；通用节点轮播不能表达人工认可及设计来源。

范围：为角色项目、原画依据、部件、视图、候选、运行、选定结果和审核状态建立最小关系；区分原画事实与推测。运行只追加候选；选择指向稳定版本。节点界面状态由项目资产派生。保留部件独立修改要求及共同设计约束。

验收：P06、P07 对应行为通过；成功／失败重跑都不改选定版本；选择新结果前，下游仍引用旧版本；上游变更标记待复核，不付费重跑；不同部件纠错历史不串用；关闭重开后的资产关系与选择一致。没有可用结果时应明确为空，不能伪造历史。

交付：领域契约、版本与选择操作、涉及状态转换的回归测试。只覆盖单角色最小闭环，不扩展团队权限。

## CRB-03：能力化 Provider 及多参考输入契约

问题：现有前端支持多输入，但 OpenAI handler 只发送第一张图；厂商模型配置不等于业务所需能力。

范围：定义生成／编辑／多参考／遮罩能力与输入限制；项目默认、节点覆盖与实际调用记录；先实现一条获准路径，预留第二个兼容适配器并以固定响应夹具验证。参考输入携带用途和固定顺序；明确目标图与保留视图。凭据与可导出项目分离。OAuth 为独立实验入口，不复用 API 成功标记。

验收：P01、P04 通过；超过数量、尺寸或 mask 能力时请求前报缺口，不截断；请求构造测试覆盖两张不同参考和三张参考；输入图像／约束不因更换兼容 Provider 丢失；模板和日志不包含凭据。模拟契约测试与真实调用结果分别记录。

交付：最小能力接口、首个适配器及契约测试、第二入口接入说明。具体默认模型须由 CRB-07 实测决定，不以文档中示例名写死业务节点。

## CRB-04：请求状态、费用授权及保守备用策略

问题：上游一般错误自动回退，无法区分已执行但丢响应；取消本地等待也不证明上游撤销。

范围：默认关闭通用 fallback；区分未提交、提交中、完成、明确失败、结果未知、取消本地等待；保存请求记录。实现显式备用允许范围和预算控制，API Key 存在不等于付费授权。服务支持状态查询时先查询；不支持时保留未知并让用户决定。

验收：P02、P05、P06 通过；网络丢响应不自动发第二次；已知未执行失败只有在满足能力和授权时回退；内容拒绝、输入错误及质量不满意不自动换服务；无法控制预算时暂停；重开不自动重提；所有情况保留已选资产。费用未知不显示零。

交付：执行状态与费用规则、可见状态提示、模拟限流／网络丢失／取消／备用失败的回归证据。

## CRB-05：单部件生成与连续优化的业务界面

问题：通用画布需要用户自己拼提示和上下文，尚未提供以部件为单位的生产流程。

范围：导入图片、文字／框选指定、部件确认、生成、并排比较、选择和继续优化。自动带入原画依据及该部件当前有效约束；遮挡补全在任务内处理并标推测。优化指定视图，满意视图仅作为参考，支持从旧候选另开分支。

验收：无 SAM、无 Mask 可走完整单部件路径；歧义可澄清；修改背面时正面文件哈希不变；未批准候选可优化，选中和批准分开；失败后用户仍可选择或导出旧结果。业务节点名称不绑定厂商。自动测试覆盖关键数据流，人工操作确认主要交互可完成。

交付：可操作的业务闭环及一个默认单部件预设。不先做整套多视图批处理和复杂通用编排。

## CRB-06：可迁移保存、恢复和参考包导出

问题：上游文件读写可用，但不足以证明角色来源、推测、选择及历史图片可恢复，当前路径形式也有平台差异。

范围：项目清单与独立资产文件；原子保存、相对引用、缺失文件提示；保存与模板分开。导出选定图片、总览、部件／视图说明、推测与审核状态及资产清单。允许带状态导出未审核候选。

验收：真实文件读写及 P03 继续通过；迁移项目到新目录可加载；重开可从选定候选继续优化；保存中断不破坏上一有效项目；缺失一张图不清空其他资产；未运行 SAM 不影响默认参考包；导出图片哈希与所选候选一致，清单不含凭据或绝对本机路径。

交付：项目读写、迁移与导出、真实临时目录集成测试。测试结束保留用户数据，只清理测试自建目录。

## CRB-07：真实资料质量、成本与 Provider 替换验证

问题：本轮没有真实生成调用，无法判断个人生产价值或给出默认模型。

范围：执行验证报告 Q01–Q04 矩阵；先一个入口，再第二个兼容入口；记录原画哈希、调用、输出、人工评审、等待和每个合格部件总成本。订阅和 API 独立报告。先与用户确定素材、云端发送范围及费用上限。

验收：按报告中预先确定条件记录每个样本通过／未通过；保存重开和导出全链完成；第二个真实入口证明兼容切换与混用，不只靠 mock。给出明确的默认 Provider 建议、适用场景和失败边界；无可接受组合则记录不通过并重新评估，而不宣布产品可用。

交付：实际图片与调用记录留本地，仓库提交脱敏结果报告、选型更新及未通过问题。缺少素材、账号、预算或模型师判断时保留待验证状态。

## CRB-08：本地 SAM 精确提取专项验证（可选）

问题：已确认 RTX 4060 8GB，但尚无模型运行证据。

范围：选择一个可获取且适合该设备的分割候选，测试框、正负点、遮罩修整、透明导出及同任务重试；按实测再决定 SAM 版本和运行环境，不一次安装整个候选清单。

验收：记录输入尺寸、峰值显存、冷启动／热运行耗时和边界质量；连续使用资源可恢复；不足时可降规模或手工／导入遮罩；默认生成路径不受影响；不调用收费云分割。文字定位只有支持时开放。

交付：独立性能／效果记录与接入或暂缓结论。未通过不阻塞 CRB-05 的无 Mask 路径。
