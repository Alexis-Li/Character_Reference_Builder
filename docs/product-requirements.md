# 产品需求

**更新日期：** 2026-09-10

**文档阶段：** 正式立项前需求评审稿

**产品定位：** 面向 3D 角色／服装模型师的节点式参考资料生产工具

本文是产品目标、功能、前端交互、范围及验收的唯一维护入口。需求变化直接修改对应章节；实施顺序见[开发任务](first-development-tasks.md)，技术取舍和实测证据分别维护，不另建平行需求或补充说明。

## 1. 产品目标与范围

产品将角色原画整理、补全为可供 3D 建模使用的参考资料。

主要使用任务是将立绘整理为保持设计一致性的 A-pose，并逐个生成、优化部件多角度图。模型师可以将选定图片交给外部 3D 生成工具，或用于后续人工建模。产品交付参考图片，首版不承担外部 3D 生成服务的自动接入。

核心目标：

- 保持原画已经明确的设计。
- 补齐姿态、视角、遮挡及部件结构信息。
- 支持模型师审核、纠错和局部返工。
- 支持在生成结果后继续连接优化节点，通过多轮修改形成可用参考。
- 保留参考来源、推测范围和人工审核状态。

优先级为：**保持原设计 > 补足建模信息 > 画面美化。**

首版面向个人工作的人形角色及服装模型师，覆盖写实和风格化角色、服装、鞋、护甲及穿戴附件。头部、头发可以作为部件组织，但首版不提供专门的毛发制作或面部拓扑流程。产品用于个人工作，不以商业发布、团队分发或 SaaS 产品化为目标；导出资料可用于建模交接。

采用“云端智能模型 + 本地工具节点”的混合模式。设计理解、推理、生成、编辑及语义一致性检查优先由云端模型承担；适合本机稳定执行的分割、辅助检测和常规图像处理优先本地运行。云端调用按所需能力选择 Provider，不绑定固定厂商。

选型以实际效果、稳定性、速度、易用性和接入成本为主。不因不支持商业分发而直接排除适合个人使用的工具，但仍核对实际使用条件。个人使用不等于任意模型、权重或账号调用方式都可用。

产品媒介范围仅包括用于建模参考的静态图像及其结构化资料。音频和视频的导入、采集、播放、生成、编辑、工作流节点、Provider 能力与输出永久不纳入产品；这不是首版延期项。复用底座中的相关实现只算迁移残留，应在不破坏图像路径与旧项目可诊断性的前提下移除。

不纳入首版：

- 非人形生物、复杂机械角色的专用流程；
- 本地大型生成模型的完整生产流程及模型训练；
- 自动生产级建模、拓扑、UV、绑定及动画；
- 工业纸样、服装物理仿真或精确尺寸反推；
- DCC 实时同步；
- 通用绘图社区、模型训练及素材市场。

交付物是建模参考，不是精确测量图或最终 3D 资产。

## 2. 典型用户场景

| 场景 | 用户路径 |
| --- | --- |
| 只有正面或 3/4 原画 | 确认设计 → A-pose → 多视图 → 拆件 → 指定部件 → 生成参考 |
| 已有合格 A-pose | 直接使用，不强制重新生成 |
| 已有部分多视图 | 使用已有设计依据，只补缺失信息 |
| 只需要一个部件 | 框选或文字指定 → 确认目标 → 云端图像模型生成参考 |
| 部件存在遮挡 | 根据原画和已有视图补全，人工确认推测内容 |
| 需要精确边界或透明提取图 | 指定部件 → SAM 分割 → 人工修整 → 提取或继续生成 |
| 修改原画或替换候选 | 查看受影响结果 → 局部返工，保留无关结果 |
| 部件多视图还原程度不足 | 连接参考优化节点 → 补充修改要求 → 修改选定视图或整组 → 比较选择 |
| 需要尝试不同修正方式 | 从同一结果分支连接优化节点 → 分别生成 → 选用满意版本 |

仅需要部件参考时，不要求先生成 Mask，也不要求安装本地 SAM。

## 3. 设计依据与人工控制

### 3.1 资料身份

资料必须区分：

- 原画依据；
- 用户补充说明或明确的设计更正；
- 有指定用途的辅助参考；
- 未确认的 AI 推测；
- 已确认、可用于建模的 AI 推测。

AI 分析结果仍属于识别结果，不自动成为原画事实。

### 3.2 冲突与约束

多张正式资料冲突时，指出具体差异，由用户确认采用的依据。辅助风格参考不能自动改变结构、数量或左右关系。

用户可确认需要保持的轮廓、比例、配色、图案、数量、层级、连接及左右关系。这些约束进入后续生成与检查，但不承诺模型绝对遵守。

普通任务提示词不能静默推翻已确认约束；明确更正设计时，更新依据并提示受影响结果。

### 3.3 推测

缺失设计允许推测，经人工确认后可继续使用，但始终保留推测来源。无法准确定位推测区域时，明确标注整张参考包含推测。

## 4. 默认工作流与可选分支

### 4.1 默认完整流程

**资料输入 → 原画理解 → 设计依据确认 → A-pose → 多视图 → 建模拆件 → 框选／文字指定部件 → 部件参考生成 → 一致性检查 → 人工审核选择 → 输出。**

A-pose、角色多视图和部件参考结果后均可继续连接参考优化节点。用户可以直接提出修改要求，也可以根据一致性检查的问题继续优化；由用户决定何时选定结果用于后续生产或导出。

### 4.2 单部件快捷流程

**原画及必要说明 → 框选／文字指定部件 → 部件参考生成 → 检查与选择 → 输出。**

无需先生成角色 A-pose、多视图或完整拆件清单，但需要明确目标部件及其设计依据。

### 4.3 可选精细分割流程

**选定图片与部件 → 本地 SAM 精细分割 → 遮罩确认／修整 → 精确提取或导出。**

分割结果也可以作为云端图像生成任务的辅助参考。双方职责为：

- 云端模型负责理解设计、识别目标、补全结构和生成参考。
- SAM 只负责指定图片中的精细分割。

只有需要像素级 Mask、透明提取图或明确边界提取时，才由用户插入 SAM。生成失败、部件遮挡或画面复杂，不自动触发 SAM，也不自动安装或运行本地分割模型。

已有合格资料可以替代生成阶段；已有合格遮罩可以替代 SAM。跳过阶段后缺少必要信息时，提示补充，不虚构输入。

### 4.4 连续优化与分支

**生成结果 → 参考优化 → 查看或检查 → 继续优化／分支比较 → 人工选择 → 输出。**

优化节点可以连续连接，也可以从同一候选分出不同优化方向。未批准的候选可以作为优化输入，检查报告不是继续优化的前置条件。

用户选择需要修改的单个或多个视图，其他满意视图作为一致性参考；也可以明确选择整组优化。每轮产生可比较的新候选，原结果保留。

### 4.5 工作流预设

预设是可加载和修改的起点，用户可增加、跳过或替换阶段，保存自己的工作流。默认提供少量高价值入口，不要求逐一运行或安装其全部可选工具。

| 预设 | 默认路径与用途 |
| --- | --- |
| Character Full Pipeline | 资料输入 → 原画理解／依据确认 → A-pose → 多视图 → 拆件 → 指定部件 → 参考生成 → 检查、选择与输出；生成阶段均可接连续优化 |
| Turnaround Only | 原画或已有 A-pose → 按需姿态整理 → 补齐所需视角 → 比较、优化、选择与输出；已有视图保留 |
| Part Reference | 原画及说明 → 文字／框选指定 → 确认目标 → 部件参考 → 优化、比较、选择与输出；首批默认预设，无 Mask 前置条件 |
| Precision Part Extraction | 图片与目标区域 → 本地 SAM → 遮罩确认／修整 → 精确提取或输出；需要时继续生成部件参考 |
| Garment Decompose | 原画 → 分析 → 拆件规划 → 人工调整 → 选择需处理的部件；是完整流程的拆件入口，可接生成或可选分割，不强制生成 Mask |
| Detail Recovery | 原画及局部目标 → 部件参考中的遮挡／细节补全 → 比较、继续优化与输出；复用部件生成能力，不新增必经恢复节点 |

完整角色、仅多视图、单部件与精确提取为 MVP 预设入口；服装拆件和细节恢复保留为可复用子流程，按实际使用收益呈现为入口或预设变体，不增加独立模型依赖。首批先交付单部件预设，具体顺序见开发任务。

工作流预设描述流程，Prompt Preset 保存常用自然语言要求，Reference Template 规定服装、物件或细节参考的表达方式，三者分别选择和保存。加载预设不能静默提交请求，也不能覆盖现有项目资产与人工选择。

## 5. 节点系统与核心节点需求

### 5.1 组合与执行原则

每个节点代表用户能够理解的生产任务。用户可以自由连接、分支、合并兼容输入、插入自然语言要求或跳过不需要的阶段，不强制运行固定流程。

支持重复执行、单节点重跑、上游结果缓存、节点禁用、节点组、工作流保存与预设、输入输出预览。合并多路参考时保留每张图的用途和来源；合并候选不等于自动选定或批准。连接只组织数据，不自动启动云端调用。

节点接收明确版本的输入，生成结果追加为候选；选定结果向下游传递，不随“最新输出”静默替换。优化节点可以显式接收未批准的候选。缓存、失效和恢复遵守第 10 节，画布操作见第 12 节。

设计锁定、对称属性和参考来源随上下文传递；可通过专用节点编辑，但不要求为了继承这些信息额外放置必经节点。普通工作流不暴露采样器、VAE 等模型内部步骤。

### 5.2 节点间的逻辑数据类型

以下定义产品层的数据含义，不指定代码接口或序列化格式。用户通过图片、名称和端口提示理解连接，无需手写数据结构。

| 类型 | 内容与用途 |
| --- | --- |
| Image | 单张图片及稳定版本、来源、用途和所属项目 |
| Image Set / Reference Set | 多张参考及各自用途、视角和顺序；不能将辅助风格图默认为正式设计依据 |
| Mask | 绑定具体图片版本和部件的像素遮罩 |
| Region | 绑定图片的框、正负提示点或标注区域及目标名称；不等同于 Mask |
| Text | 自然语言说明、修改要求或常用提示，带项目／部件／任务作用范围 |
| Design Data | 角色比例、服装结构、层级与连接关系、设计约束、依据和不确定项 |
| Part Data | 单个建模部件的名称、归属、左右、对称性、有效要求及参考关系 |
| Part Set | 多个部件及其组织关系、所需输出和生成选择 |
| View Set | 同一角色或部件的关联视图，标明视角、侧别、图片版本和推测状态 |
| Review Result | 检查涉及的图片与版本、依据、差异、影响及无法判断项 |

端口需区分单图、参考集合、视图集合、区域与遮罩。输入不兼容时说明缺失内容；不能为了连通而丢弃参考、约束、部件身份或视角。每个节点的必要输入完整后才可执行；可选输入缺失不应被伪造。

### 5.3 Image Input / Reference Input：资料输入

- **输入：** 本地单张图片、多张原画或辅助参考，以及用户说明。
- **输出：** Image 或 Reference Set，附图片用途、视角、备注和设计来源。
- **操作：** 导入、预览、排序、增删参考，指定主参考与辅助参考，并标注 Front、Side、Back、Detail 或 Style Reference 等用途。
- **要求：** 多张资料归入同一角色项目。用途与视角分别表达，已有背面图作为设计依据传递；冲突资料由用户确认，不自动融合。

### 5.4 Natural Language / Prompt：自然语言要求

- **输入：** 用户文本或已保存的 Prompt Preset。
- **输出：** 带作用范围的 Text，可同时连接分析、姿态、多视图、拆件、生成、优化和检查节点。
- **操作：** 多行编辑、保存与加载预设；允许在工作流中按需插入，避免逐个打开 AI 节点修改复杂提示。
- **要求：** 支持“裙摆三层，不允许合并”“只修正背部腰带”等生产要求。与已确认约束冲突时提示处理，普通提示不能静默更正设计。模型内部提示配置不作为普通用户必填项。

### 5.5 Design / Garment Analyzer：原画与服装理解

- **输入：** 原画、其他设计参考及用户补充说明。
- **输出：** 可编辑的 Design Data，以及供 Part Planner 使用的建议部件与不确定项。
- **识别内容：** 身体比例、主要轮廓、风格、服装层级、部件数量、左右和对称关系；分别表达“覆盖”“固定在”“位于外层”和父子归属。
- **操作：** 用结构树查看角色、外套、衣领、袖口等关系，允许人工增删、重命名、合并和调整归属。
- **要求：** 从建模制作角度提出建议，不停留于图像语义分类。识别结果附依据，不自动转为用户已确认的设计事实。

### 5.6 Reference Lock / Design Confirmation：设计锁定与依据确认

- **输入：** 原画依据、Design Data 及用户明确的设计要求。
- **输出：** 已确认的设计约束与资料采用决定，保留来源和作用范围，随 Design Data 或 Part Data 传递。
- **操作：** AI 可提出锁定建议，用户逐项修改或确认轮廓、配色、图案、数量、装饰位置、长度比例、层级、连接及左右关系。
- **要求：** 项目共同约束自动继承，部件要求独立保存。更正约束后提示受影响结果；“锁定”表达生成和审核要求，不承诺模型绝对遵守。具体依据规则见第 3 节。

### 5.7 A-Pose Normalize：姿态整理

- **输入：** 角色原画与必要参考、Design Data、有效约束及自然语言要求。
- **输出：** A-pose 候选 Image，保留设计依据、推测说明与审核状态。
- **操作：** 可选保守模式与标准模式；保守模式优先保持服装结构，标准模式提高姿态规范程度，但不能静默改动设计。
- **要求：** 保留比例、长度、配色、图案、数量、装饰与层级。已有合格 A-pose 可直接使用；结果可比较、选择或连接参考优化。姿态验收见第 8.1 节。

### 5.8 Turnaround Generator：多视图生成与补全

- **输入：** 角色或部件参考、已有 View Set、设计约束及目标视角。
- **输出：** 带视角和侧别的 View Set，各视图保留独立原图与候选版本。
- **操作：** 默认正、侧、背三视图，可按需补前后 45° 或另一侧；已有视图直接作为依据。允许指定角色保持不动、相机绕角色改变观察方向，尽量固定相机高度和焦距，使用中性背景与弱化戏剧光照。
- **要求：** 保持对象姿态、尺度与观察条件可比较；相机参数是参考表达要求，不冒充真实几何控制。支持单视图返工及保留视图约束，六／八视图和复杂相机路径延后。详细规则见第 8.2 节。

### 5.9 Part Planner：建模拆件规划

- **输入：** Design Data、原画与已有参考，可附用户指定的目标部件。
- **输出：** Part Set 和各部件的 Part Data，包含是否生成、参考类型、优先级及必要的进一步拆分。
- **操作：** 新增、删除、拆分、合并、重命名、调整父子归属和左右／对称关系。
- **要求：** 判断哪些部件需要独立多视图、哪些只需细节图或已有参考。例如外套需要整体视图，衣领和扣件可只需局部结构图；裙摆可按内外层拆分。仅在确认完全对称后建议复用一侧。用户决定实际生成清单，不默认全量运行。关系规则见第 8.3 节。

### 5.10 Region / Box：部件指定

- **输入：** Image、目标部件名称或说明，可附 Part Data。
- **输出：** 图片版本、Region 与目标部件信息一并传递；框选不替代完整原画上下文。
- **操作：** Box 矩形框选、Point 正向点、Exclude Point 排除点；需要时在图片工作区用画笔修整。区域可手工命名。
- **要求：** 同时支持只用文字指定部件。区域可送到直接生成或可选分割，不强制进入 SAM；“框里有手和腰带”时可明确只要腰带。目标歧义处理见第 6.1 节。

### 5.11 Segmentation / SAM：本地精细分割

- **输入：** 图片、框或正负点，可附初始 Mask；文字定位仅在所选本地能力已验证支持时开放。
- **输出：** 绑定原图版本的 Mask、裁切图、Alpha 透明图及边界框，支持多个候选遮罩。
- **操作：** 选择候选、增删修整、确认、重新分割或导入外部遮罩。
- **要求：** 只提取可见像素，不补全遮挡，不自动安装或运行；不可用时不阻断无 Mask 路径。不通过付费云分割替代本地工具，详见第 7 节。

### 5.12 Part Reference Generator：部件参考生成

- **输入：** 原画依据、目标部件、有效 Design Data / Part Data、用户要求；已有多视图、裁切和 Mask 按需使用。
- **输出：** 所属部件的 Image 或 View Set 候选，附来源与推测范围。
- **操作：** 选择 Garment Turnaround（服装）、Object Turnaround（物件）或 Detail Sheet（细节）参考模板及必要视角。
- **要求：** 自动继承该部件的设计上下文，不让用户重复描述角色；支持无 Mask 生成。保持穿戴或装配形态，遮挡补全在本任务内完成，输出与补全规则见第 6.2–6.4 节。

### 5.13 Reference Refiner：参考优化

- **输入：** 明确候选版本、原画依据、当前有效约束、本轮要求、修改范围及需保留的视图。
- **输出：** 仅修改范围的新候选，与输入版本及优化分支关联。
- **操作：** 单图、多图或明确整组优化；继续连接优化节点，或从历史候选另开分支后比较选择。
- **要求：** 未批准候选也可继续优化；未修改视图原文件保持不变。失败不覆盖旧结果，冲突不自动扩大修改范围，详见第 6.5 节。

### 5.14 Occlusion Recovery 与 Symmetry / Mirror Assist

遮挡补全由 Part Reference Generator 内置承担：输入已有视图、原画、用户说明及相关结构依据，输出带推测标记的补全候选，不要求搭建独立补全节点链。手挡腰带、头发挡衣领、外套挡内搭等均在部件任务内处理，见第 6.4 节。

对称辅助作为部件属性与约束编辑能力，区分完全对称、仅基本结构对称和左右设计不同。用户确认完全对称时，可将一侧设计作为另一侧约束；部分对称只复用共同结构，保留两侧差异。普通图片翻转保留来源并正确标记侧别，不能据此认定另一侧原画存在；自动镜像整套部件延后。

这两项能力可通过业务节点属性使用，不作为默认工作流中的必经独立节点。

### 5.15 Consistency Checker：一致性检查

- **输入：** 待检查图片或 View Set、原画依据、有效 Design Data / Part Data 及约束。
- **输出：** Review Result，列出新增／缺失部件、数量、层级、轮廓、长宽比例、左右、配色、图案、材质观感及视图矛盾。
- **操作：** 打开问题涉及的图片、纠正判断、忽略或接受已知问题，将具体问题送入参考优化。
- **要求：** 给出依据与影响，不能只给分数；例如“三层裙摆变为两层”“背面腰带宽于正面”。无法判断就标记不确定，无法定位就不伪造高亮区域。审核规则见第 9 节。

### 5.16 Compare / Select：比较与选择

- **输入：** 两个或多个候选 Image / View Set，可带原画或 Review Result。
- **输出：** 用户明确选定的候选版本引用，供下游或导出使用；不修改输入图片。
- **操作：** 并排、叠加、放大、同步缩放和平移、历史分支比较及选定。
- **要求：** 选定不等于批准；查看另一张图不能改变下游选择。重跑成功或失败均保留原选择，用户可以继续优化或导出旧结果。

### 5.17 Approval Gate：人工确认门控

- **输入：** 待确认的设计数据、拆件方案或候选图片。
- **输出：** 用户批准后放行的对应版本与确认记录。
- **操作：** 暂停等待，提供批准、驳回、编辑及重新生成。
- **要求：** 默认业务结果内已有确认入口；用户需要明确暂停自动流程时才插入门控。驳回暂停该门控下游，不删除结果或阻止无关分支；批准后也不超出已授权的云端任务及费用范围。

### 5.18 Preview / Gallery / Export：预览与输出

- **输入：** 图片、视图集合、选定候选或指定部件资产。
- **输出：** 可浏览的结果集合，或第 13 节定义的参考包及资产清单。
- **操作：** 缩略图浏览、大图查看、定位部件与版本、选择导出范围。
- **要求：** 浏览和导出已有资产不触发生成。按交付范围检查归属、视角、推测和审核状态；允许明确带状态导出未审核资料，无 SAM 不构成默认参考包缺失。

### 5.19 图像工具与流程辅助

基础图像工具按第 7.1 节提供 Crop、Resize、Flip、Rotate、Pad、Mask、Composite、Annotation、Contact Sheet 等操作。节点接收图片及必要区域／遮罩或参数，输出保留来源的新图或标注，不改写输入原图；用户也可在专用图片工作区调用，不必为每个操作搭节点。

流程辅助保留 Switch／Router 的设计候选：将用户选定的输入或满足明确条件的分支送至下游，显示实际路由；未选分支不因切换而自动生成。Group 和 Comment / Note 用于组织与说明。复杂条件编排与动态路由后置，首批通过显式选择和普通分支完成生产路径。

## 6. 部件指定与云端图像模型直接生成

### 6.1 指定方式

用户可以：

- 框选目标，例如肩甲或腰带；
- 文字指定，例如“角色左肩的金属肩甲”；
- 框选并补充说明，例如“只处理框中的腰带，不包含手和挂件”。

支持使用带红框等标记的完整设计图和文字说明指定部件，也支持补充局部截图。框线属于目标指示，不属于角色设计，不应出现在生成的部件上。

不强制文字指定转成框选，也不强制先生成遮罩。

出现多个同名部件、左右歧义或范围不明确时，展示理解结果并请用户确认。不能可靠定位时，请求更具体的说明或框选，不默认转交 SAM。

框选主要表达目标范围，不等于精确裁切边界，也不表示允许丢弃框外设计上下文。

### 6.2 生成输入

部件参考生成必须使用：

- 原画或用户选定的设计参考；
- 目标部件的框选、文字说明或二者；
- 已确认的设计约束；
- 与该部件相关的角色、层级及连接信息；
- 用户要求的参考表达方式。

已有多视图、细节图、裁切图和 Mask 均为按需使用的辅助资料，不是固定必填项。

用户不需要为每个部件重新描述整个角色。

不同部件各自维护生成与优化上下文，共享原画及已确认的共同设计约束，不自动混入其他部件的候选和纠错历史。同一部件的连续优化保留当前有效的修改要求；用户更正旧要求时，以明确更正后的要求为准，并可回看历史。

### 6.3 生成结果

支持三类参考：

- **服装参考：** 保持穿戴形态的必要视图。
- **物件参考：** 鞋、护甲、腰带、挂件等的独立视图。
- **细节参考：** 衣领、扣件、接缝及连接位置等局部表达。

默认保持穿戴或装配形态。服装不自动变成平铺纸样，独立展示不丢失佩戴方向及连接位置。

只生成建模所需信息，不要求所有部件都生成完整多视图。已有足够资料的细节可以直接放大查看，不强制重新生成。

云端图像模型输出属于生成参考，不是对原图像素的精确提取，不能将其当成保持原始边界和纹理像素不变的资产。

### 6.4 遮挡与补全

已有其他视图时优先利用其设计依据；没有依据时允许生成推测。

遮挡补全属于部件参考生成的内置处理，按目标部件、其他视图、原画上下文及用户要求进行；可提供“补全被遮挡区域”选项，不要求额外搭建补全节点链。涉及重要连接、层数或不可见结构的设计选择时，在该任务内先确认补全方案，再继续生成；明确标记无依据的推测。

用户可以分别返工补全方案和最终参考表达。SAM 不承担遮挡恢复或不可见结构推断。

缺陷修正应针对指定部件、视图或区域。不能可靠完成局部编辑时，允许生成替代候选或导入外部修正版，再重新检查。

### 6.5 参考优化

参考优化节点接收原画依据、用户选定的当前结果、当前有效约束和本轮修改要求。用户可指定需要保持的其他视图，并选择单个视图、多个视图或整组作为修改范围。

- 只生成所选修改范围的新候选；未选视图沿用原图，不重新生成或替换。
- 未选视图作为一致性参考时，仍可能需要云端读取，运行前说明输入范围及可获得的费用估计。
- 修改要求可以是恢复原画轮廓、修正装饰、调整姿态或解决视图间矛盾，不要求用户先取得检查报告或 Mask。
- 每个新候选可继续连接优化节点，也可返回任意已有候选另开分支。
- 优化失败或效果不满意时保留原结果，不自动扩大为整组重生成。
- 如果所选修改会与保留视图产生冲突，说明冲突，由用户决定调整要求或扩大修改范围。

对照检查应覆盖修改结果与原画，以及修改结果与保留视图的关系。其他满意视图是参考约束，不保证模型一次遵守；偏差可以继续通过后续节点修正。

## 7. 本地工具与 SAM 可选精修

### 7.1 本地工具范围

本地工具不依赖额外付费 API、按次云服务或第三方订阅；不得为了接入便利将这些工具转交付费云服务。这里的费用边界不代表没有硬件、安装、存储和运行成本。

优先验证用户实际 RTX 4060 级别设备上的稳定运行能力，记录显存、输入分辨率、耗时及峰值资源占用；不能仅凭显卡系列名承诺所有模型可运行。

| 范围 | 产品要求与优先级 |
| --- | --- |
| 基础图像工具 | MVP 提供框选、标注、裁切、缩放、旋转、翻转、留白、透明合成、比较、总览排版和导出；按工作需要使用，不强制逐个搭节点 |
| 精确边界工具 | 首版可选 SAM 分割，配合遮罩增删、扩张、收缩、柔化和透明提取；独立验收 |
| 扩展检测与处理 | GroundingDINO 等定位、DWPose／OpenPose 姿态、BiRefNet／RMBG 抠图、Depth Anything 深度、Real-ESRGAN 超分，以及边缘、线稿、轮廓提取，均为候选；按实际任务收益和本机验证结果后续纳入 |

SAM／SAM2／SAM3 是分割候选，不承诺全部支持或优先采用最大、最新版本。本机资源不足时提示原因，允许调整输入规模、改用已验证的轻量工具、手工处理或导入结果；涉及精度变化时说明影响。不会静默上传原图或改用收费分割。

### 7.2 SAM 的使用边界

SAM 适用于：

- 导出像素级部件 Mask；
- 从指定图片提取透明部件图；
- 明确排除相邻物体，修整目标边界；
- 为后续支持相应能力的处理提供遮罩或提取参考。

SAM 不适用于判断部件如何建模、补全被遮挡结构、生成新视角或自动修正生成结果中的设计偏差。

节点支持框、正负点、多候选遮罩选择、简单增删修整，以及导入外部修正遮罩。一个部件可以对应多个不连通的可见区域。文字提示仅在已验证的分割模型或本地定位组合支持时提供，不把文字定位假定为所有 SAM 版本的通用能力。

遮罩绑定具体图片版本和部件，不能直接跨视图或跨生成版本使用。对生成图进行分割，只能提取该生成图已有内容，不能借此证明其忠于原画。

分割失败时允许修整、换图或放弃分割，保留已有候选。未依赖该遮罩的生成和导出路径继续可用。

传入 Mask 不代表当前 Provider 必然支持严格遮罩编辑；若当前调用方式不支持，说明差异；仅在用户接受非严格边界结果时按辅助参考使用，否则暂停该任务或改选支持严格遮罩编辑的 Provider。

## 8. A-pose、多视图与拆件

### 8.1 A-pose

默认保守保持设计。用户可以提高姿态标准化要求，但不得静默改变服装结构。

重点审核比例、服装长度、数量、图案、装饰位置、层级和左右关系。无法消除的遮挡应明确说明，不任意挪动穿戴部件来制造无遮挡效果。

### 8.2 多视图

默认正、侧、背三视图，可增加前后 45° 及另一侧。

- 左右使用角色自身方向，并注明侧面所展示的一侧。
- 非对称设计不得默认镜像。
- 缺少另一侧关键结构时提示补充。
- 保持可比较的姿态、比例、尺度和地面基线。
- 支持人工排列与对齐，不通过拉伸形体伪造一致。
- 使用便于读结构的背景与光照。
- 可单独重做某个视图。
- 保留独立视图原图，总览图不替代单视图细节。

目标是便于建模观察的近正交参考，不承诺二维生成获得真实几何一致的正交投影。

### 8.3 拆件

拆件保持三层职责分离：

1. **决定拆什么：** 云端模型结合建模逻辑提出制作单元和参考任务，由用户调整确认。
2. **指出在哪里：** 用户框选、点选、文字说明或可选本地目标定位工具明确目标。
3. **获得像素边界：** 仅需要精确提取时使用本地 SAM，必要时人工修整。

原画理解提供结构依据，不把制作规划、空间定位和像素分割合并成一个自动分割任务。

每个部件明确名称、归属、数量、左右、覆盖、连接关系、可用参考及所需输出。父子归属、覆盖和固定关系分别表达。

用户可新增、删除、拆分、合并和重命名，只生成所选部件，不默认批量生成全部拆件。部件变化后重新确认已有资料归属，不自动删除资产。

## 9. 一致性检查与人工审核

检查三个层面：

1. 生成结果与原画及确认设计是否一致。
2. 同一部件不同视图是否矛盾。
3. 独立部件与角色整体的比例、连接和层级是否冲突。

检查数量、轮廓、比例、左右、配色、图案、材质观感、覆盖和连接。

每条问题包含涉及的图片或部件、比较依据、具体差异及是否影响建模。无法判断时明确保留不确定性。

不以单一评分表示通过，也不把未发现问题视为质量保证。

用户可选中、批准、驳回、纠正检查判断或带说明接受已知问题。选中候选不等于批准。

默认在设计依据、A-pose、多视图、拆件和部件输出阶段提供人工确认位置；使用 SAM 时增加遮罩确认。用户可先连接优化节点继续修改候选，满意后再确认用于后续生产。无需每次额外放置审批节点。

一致性检查为用户提供修改线索，可在中间阶段重复使用，也可将问题带入优化节点。AI 检查不决定迭代次数，不要求首轮通过，由用户决定继续优化、选用已有结果或带说明导出。

## 10. 执行、版本与失败恢复

画布支持连接、分支、预览、单任务执行、局部重跑、禁用、节点组和保存。连接需满足实际输入要求，不兼容时说明原因。

- 显示排队、执行中、等待确认、完成、失败、取消和结果状态未知。
- 重跑产生新候选，保留已有选择。
- 连接优化节点产生独立的后续候选，不改写其输入版本；支持回看优化链、比较分支及选择结果。
- 上游修改后标记受影响结果待复核，不自动覆盖或付费重跑。
- 不相关分支可以继续执行，失败不清空项目。
- SAM 不可用只影响需要分割的任务。
- 关闭重开后恢复资料、选择及审核状态，不默认重新提交请求。
- 断网时仍可查看已保存资料、标注和导出；已安装且无需联网的本地工具继续可用。
- 支持暂停后续任务和取消；不承诺取消能撤销已发生的云端费用。

请求可能已经执行时，优先确认状态。无法确认则提示可能重复消费，由用户决定是否重试，不自动切换服务重复提交。

## 11. 能力边界、Provider 与费用

### 11.1 三层职责

| 层次 | 职责 | 边界 |
| --- | --- | --- |
| 业务工作流（Business Workflow） | 原画／服装分析、A-pose、多视图、拆件规划、部件参考、参考优化及一致性检查 | 定义用户任务、设计上下文和预期结果，不使用厂商专用节点名 |
| 云端能力接入（Provider Layer） | 为业务任务选择具备所需能力的模型、授权方式及备用服务 | 管理能力适配与调用状态，不决定部件划分和设计依据 |
| 本地工具（Local Tool Layer） | 分割、辅助检测、遮罩和常规图像处理 | 处理具体图像或区域，不替代设计推理，不依赖额外付费云工具 |

三者按职责区分，不是必须依次运行的三个阶段，也不预设代码架构。

### 11.2 按能力选择

| 业务任务 | 必要能力 |
| --- | --- |
| 原画／服装分析、拆件规划、一致性检查 | 视觉理解与推理，能表达结构关系、依据和不确定性 |
| A-pose、部件参考生成 | 参考图条件生成或图像编辑，能使用目标说明和设计上下文 |
| 多视图补全 | 多参考图条件生成／编辑，能利用已有视图和设计依据 |
| 参考优化 | 图像编辑或受参考约束的重新生成；多视图任务需使用保留视图 |

生成、参考图编辑、多参考输入和严格遮罩编辑分别判断；不能从支持一种推定支持全部。能力匹配同时检查输入数量、尺寸及输出限制。不满足要求时说明缺口，允许用户改选 Provider 或明确调整任务，不能静默丢弃参考图、遮罩或约束。

同一工作流允许不同节点使用不同 Provider。项目可按能力设置默认 Provider，节点可显式覆盖并配置 Primary／Fallback。切换后保留业务节点、连接、角色上下文和既有结果；能力兼容时无需重搭流程，不兼容时仅阻止受影响任务并说明原因。不承诺不同模型得到相同画面质量。

### 11.3 接入与授权

支持两类接入方式，不限定厂商：

- **订阅／账号授权 Provider：** 使用用户主动接入的订阅或账号能力，可通过适用的 OAuth 等方式授权。ChatGPT／Codex 相关授权路径是优先验证候选，不是已确认的通用图像接口或产品依赖。
- **API Provider：** 用户主动配置 API Key，按对应服务规则调用。OpenAI、Gemini、即梦等仅为候选示例；实际可用性以相应入口、任务能力及使用条件验证为准。

同一厂商的订阅与 API 可以具有不同能力、额度和计费方式，分别显示。未来新增符合要求的接入方式应能用于现有业务任务。

支持登录、退出、重新认证、账号切换及 API 凭据更新；有效会话正常使用不要求重复登录，支持接入方式允许的认证续期，续期失败明确提示。认证失效保留项目。区分授权成功、模型可用、任务能力支持和额度状态，未知额度或恢复时间如实标记。凭据不进入项目、模板、导出或可分享错误记录。

### 11.4 备用策略与费用控制

用户可以选择仅使用主 Provider，或为相应能力设置备用 Provider。优先已有订阅是可选偏好，不是全局强制策略；具备合适能力且用户认可成本的 API 也可作为主 Provider。

| 情况 | 行为 |
| --- | --- |
| 已确认额度不足、模型不可用或不支持任务 | 展示原因及具备所需能力的备用选项；无合适选项则暂停该任务 |
| 请求明确失败且确认未执行 | 在用户已允许的备用范围内切换，记录原请求与切换原因 |
| 请求状态未知、可能已执行 | 优先查询状态；仍无法确认则由用户决定是否重试，不自动跨服务重复提交 |
| 备用会增加 API 费用 | 默认先确认；仅在用户已明确允许的 Provider、任务范围和预算上限内自动执行 |
| 输入错误、内容拒绝或效果不满意 | 提示修改或人工选择下一步，不自动跨服务反复请求 |

主动配置 API Key 不等于允许任意付费回退。运行前显示实际 Provider、模型、输入范围、预计调用次数、计费方式和可获得的费用估计；估计与实际账单分开。无法可靠控制预算时暂停自动付费执行；即使当前没有新增 API 费用，自动切换也需处于用户允许的备用范围内。

已明确授权的备用范围与预算可以跨该范围内的后续节点复用，不要求逐节点重复确认。运行记录展示是否发生 Fallback、原入口与实际入口、切换原因、能力差异及费用状态，便于回看。

费用范围限于用户主动接入的云端智能模型能力；本地工具不另接付费工具服务。禁止静默付费、无限重试或为切换服务自动扩大生成范围。

## 12. 工作界面与项目保存

### 12.1 项目与资源

项目保存原画、说明、约束、部件关系、视图、生成候选、选择、审核意见和来源。遮罩及分割记录只在实际使用时存在。保存项目默认与节点覆盖的 Provider 偏好，不保存凭据；迁移环境后缺少相应 Provider 或本地工具时标记待配置，已有结果仍可查看与导出。

同时保存部件各自的有效修改要求、优化节点连接、分支、每轮修改范围及保留视图，重新打开后可以从选定候选继续优化。

任意结果应能追溯：

- 所属部件与视角；
- 使用的设计依据；
- 推测内容；
- 上游版本；
- 实际使用的 Provider／模型或本地工具版本，以及可获得的调用和费用记录；
- 审核状态及是否待复核。

项目保存和模板保存分开。分享模板默认不包含原画、私人说明或凭据。

项目资源面板按原画、参考、部件、视图、遮罩和候选组织，支持部件导航、缩略图筛选及拖入节点。选定与审核作为独立状态显示，资源详情展示所属部件、视角、用途、来源、推测和版本关系。支持导入外部修正版并保留来源。

云端处理前明确发送的资料和目标服务，不默认向每个任务发送整个项目。有效结果不能仅依赖可能失效的远程预览链接。

资产清单（Asset Manifest）由系统维护，用户通过资源界面查看和修改归属，无需手工编辑清单。项目至少能回答每张图片属于哪个角色、部件、视角和哪次运行：

| 关系 | 必须保留的信息 |
| --- | --- |
| 角色与部件 | 角色归属、部件标识与名称、父子关系、覆盖／连接、左右及对称关系 |
| 图片与视图 | 稳定资产及版本标识、文件引用、角色／部件／视角、原始或生成身份 |
| 生成与优化 | 运行记录、输入版本与依据、提示和有效约束、修改范围、保留视图、优化父级与分支 |
| 人工决定 | 当前选定版本、审核意见、已知问题、推测确认及待复核状态 |
| 可选资料 | 实际存在的区域、遮罩、透明图及其对应图片版本，不制造空的必填分割记录 |

修改部件归属后仍能追溯历史，生成失败不破坏这些关系。复杂清单编辑器后置，不影响清单本身随项目保存。

### 12.2 启动与主界面

采用本机 WebUI 与可双击的启动入口：启动后台后自动打开浏览器，停止入口明确，重复启动不产生多个后台。用户无需手工运行终端或多个服务；本地推理与云端接入由后台管理。首版只服务本机使用。

未打开项目时显示新建、最近项目和工作流预设入口；可恢复上次项目，可选提供最近输出快捷入口。项目操作包括打开、保存、另存为；工作流支持加载预设、保存及导入导出，与包含用户资料的项目分开。

主界面以节点画布为中心，顶部放项目、工作流、执行和设置入口，侧面提供可折叠节点库、资源与属性面板，底部提供任务和预览面板。具体尺寸与排布按实际使用调整。

布局参考：

- 顶部：当前项目名、Project、Workflow、Run、Provider 状态、Settings。
- 左侧：节点搜索、按任务分类的节点库、预设与项目资源入口。
- 中央：无限节点画布与图像缩略图。
- 右侧：选中节点的参数、自然语言要求、实际能力配置、预览与状态。
- 底部：当前及历史任务、图片比较与可展开的错误日志。

顶部 Provider 摘要可点击进入设置，显示实际连接或备用状态；支持混合入口时不暗示所有任务都由同一模型执行。视觉采用低饱和深色和少装饰，可参考 DCC 工具的信息组织，避免大面积渐变、大圆角和营销式包装。

界面采用专业建模工具的表达：图片优先、低饱和深色、清楚的文字与状态标记、适度信息密度。主界面不采用聊天布局；减少装饰，状态不能只靠颜色区分。

### 12.3 节点画布与属性

画布支持平移、缩放、从节点库拖入、右键搜索创建节点、多选与框选、复制粘贴、Duplicate、删除、撤销重做、连接、分支、分组、备注及启用／禁用。连接时提供兼容端口与自动连线提示。连接时提示输入兼容性。节点库按第 5 节业务任务和第 7 节本地工具组织，只呈现实际可用或明确待配置的能力。

节点库顶部提供搜索，候选分类如下。分类不是要求同时实现所有候选：

| 分类 | 节点／操作 |
| --- | --- |
| Input | Image Input、Reference Set、Text Input |
| Analyze | Design / Garment Analyzer、Part Planner、Consistency Checker |
| Generate | A-Pose、Turnaround、Part Reference、Reference Refiner |
| Region | Box、Point、Brush、Region Select；可复用同一标注工作区 |
| Local Tools | SAM，以及按实测纳入的 Pose、Grounding、Matting、Depth、Upscale |
| Image | Crop、Resize、Flip、Rotate、Pad、Mask、Composite、Annotation、Compare、Contact Sheet |
| Flow | Prompt、Select、Approval Gate、Group、Note；Switch／Router 为后续候选 |
| Output | Preview、Gallery、Export |

节点卡片显示任务名称、输入输出、缩略图及状态；多图输出显示缩略图列表，不只显示数量。复杂参数与细节操作进入属性面板或专用图片工作区，不塞入节点卡片。

自然语言输入提供多行编辑、常用要求保存和加载，可连接多个业务节点，明确项目／部件／任务作用范围。普通界面不要求填写 System Prompt、JSON Schema 或模型采样参数。

### 12.4 图片工作区与比较

缩略图支持悬停放大预览；双击图片进入可全屏的大图工作区，支持平移、缩放、适应窗口、原始比例查看、框选、标注及撤销重做。目标区域可以命名，并显示所属部件；应用修改才提交标注，取消保留之前结果。

启用分割时提供正负点、画笔增删、橡皮及遮罩预览，图片、目标区域和遮罩分层显示。SAM 的常规操作为输入图片与区域、查看候选遮罩、修整及确认，不暴露底层推理参数。输出可查看遮罩、裁切和透明图。

比较支持并排与透明叠加，多视图支持同步缩放和平移、排列对齐和快速切换。单图右键提供保存、复制、Open Folder 定位文件、Compare 及 Send to Node 等操作；总览不能代替原图细节查看。

### 12.5 业务结果编辑

| 任务 | 交互要求 |
| --- | --- |
| 原画理解 | 用可编辑结构树呈现部件、层级与关系，支持新增、删除、重命名、合并、调整归属及左右／对称关系 |
| 拆件规划 | 用列表或卡片展示部件、所需参考类型、是否生成、优先级、对称关系及是否需要精确提取；允许人工修改 |
| A-pose 与多视图 | 显示独立视图缩略图及设计依据，可指定待补视角；并排查看后选择、审核或单独优化 |
| 部件生成与参考优化 | 显示目标部件、输入候选版本、原画依据、有效约束、本轮要求、修改与保留视图；候选可继续优化或从历史分支 |
| 一致性检查 | 用问题列表呈现差异与影响，点击打开涉及图片；有可靠坐标时才高亮，无法定位时保留文字说明 |
| 审核与选择 | 分别提供选为下游输入、批准、驳回和接受已知问题；支持比较历史候选，运行完成不自动选定或批准 |

业务结果内提供人工确认。可选 Approval Gate 暂停所控制的后续任务，允许批准、编辑或重新生成；驳回不删除候选，不阻止无关分支或候选继续优化。

### 12.6 执行反馈与 Provider 设置

执行入口包括当前节点、选中节点、从此处继续和完整工作流，以及停止后续执行／取消本地等待。执行前检查依赖；涉及云端调用时遵守第 11 节的输入与费用规则。

节点及任务面板区分未运行（Idle）、输入就绪（Ready）、排队、提交中、运行中（Running）、等待确认、完成（Complete）、明确失败（Error）、结果未知和取消本地等待。完成但存在问题显示 Warning 及原因，上游修改导致的待复核显示 Outdated；Warning 与审核状态分开，不能把警告当作已批准。候选另行显示选定、审核与待复核状态。进度、显存、额度和费用仅显示已知数据，未知不能伪装为零或精确值。

任务面板展示当前与历史运行、实际 Provider／模型或本地工具、耗时、结果及可恢复操作，区分本地、订阅／账号和 API。错误用业务语言说明原因及下一步，技术日志可展开；超时不能直接显示为确定失败并推荐自动重试。

Provider 设置独立管理凭据、登录、退出、账号切换与认证状态。项目按能力选择默认入口，节点 Auto 解析该默认，也可显式覆盖。界面分别展示认证、模型可用性、能力限制及额度；连接成功不代表任务可执行。运行记录显示实际入口，顶部摘要不以单一“已连接”掩盖混合调用状态。

### 12.7 自动保存、缓存与性能

自动保存节点位置、连接、参数、面板状态及第 12.1 节的项目资料。浏览器刷新和重开后恢复当前选择与优化链。保存中断保留上一有效项目；迁移目录后仍可加载，缺失单张资产不清空其他内容。

运行追加候选，人工选择绑定明确版本；选择新版本前，下游仍引用旧版本。历史中可恢复候选及有效修改要求，仅清理可重建且未被引用的临时数据。

输入版本、约束和执行参数等条件一致时复用已有结果；明确“重新生成”创建新运行并展示费用。上游变化标记受影响结果待复核，由用户决定是否重跑。

画布加载缩略图，大图按需加载；避免打开项目时解码全部原图。移动节点、改提示词或连线不触发云端生成，云端执行由明确运行操作或其已授权的后续流程触发。原图与有效结果保存到本地，不依赖临时远程链接。

## 13. 导出

输出按角色、部件与视角自动组织，名称可识别且可追溯到所选候选；用户可以导出全部候选过程、仅当前有效且通过审核的结果，或指定部件。

支持导出已审核角色参考、指定部件或全部候选过程资料。

默认导出当前有效、已审核的结果，包括：

- 独立视图图片；
- 参考总览；
- 名称、视角、左右及必要连接说明；
- 推测范围、审核状态和已知问题；
- 实际存在且用户选择导出的 Mask、透明提取图。

未运行 SAM、没有 Mask，不构成默认参考包缺失。需要精确提取的特定交付任务，才检查对应遮罩或透明图是否齐备。

保留可用原始分辨率，说明不遮挡关键结构；放大图片不冒充新增真实细节。

导出前检查所选交付要求、归属和审核状态。允许显式导出未完成资料，但保留状态标记。

参考包的逻辑组织示例：

- Character / Turnaround：Front、Side、Back 等独立视图及参考总览。
- Character / Parts：Coat、Belt、Boots、Accessories 等部件及各自视角与说明。
- Character / Masks：仅包含实际存在且本次选择的遮罩与透明提取图。
- Asset Manifest：角色、部件、视角、候选和运行之间的归属，以及来源、推测、审核与已知问题。

以上是交付组织要求，不规定具体存储实现。导出清单不得包含凭据或绝对本机路径；文件应与用户所选候选一致，不能导出预览缩略图代替原始分辨率结果。导出参考包用于建模交接；可继续编辑的项目另行保存。

## 14. MVP 与复用范围

### 14.1 MVP 必须闭合

- 资料输入、用途及冲突确认；
- 设计理解与人工约束；
- A-pose、默认三视图和必要补角度；
- 可编辑拆件；
- 框选／文字指定部件；
- 无 Mask 前置要求的云端图像模型直接生成；
- 可连续连接的参考优化节点，支持选定视图优化、整组优化、分支比较和历史结果保留；
- 部件独立上下文及共同设计约束继承；
- 必要遮挡补全及推测确认；
- 衣物、物件、细节参考；
- 检查、选择、局部返工、保存与导出；
- 按能力选择 Provider、项目默认与节点覆盖、备用策略及费用控制；
- 支持订阅／账号授权和 API 两类接入的产品规则；首批实际可用入口按验证结果确定，不以接入所有示例厂商为 MVP 要求；
- 第 7.1 节列出的基础本地图像工具；
- 第 12 节的工作界面与项目交互，分批实现以支撑完整生产流程。

SAM 为首版提供的可选精修能力，不是每个项目的必经步骤或默认流程验收前提。分割功能单独验收，只有使用它的任务依赖本地模型和运行条件。

音频和视频不属于 MVP、后续候选或可选扩展。载入含相关节点的上游工作流时，兼容处理必须明确提示不支持，不得静默执行、转换或删除，也不得因此触发外部计费。

预设入口为完整角色、仅多视图、单部件参考及精确部件提取；前三者默认不包含 SAM。

延后六／八视图、连续相机路径、自动镜像整套部件、无人值守全量生成、复杂通用编排、专业绘画编辑器、多窗口、多人协作、云端项目同步、插件商城、移动端及浏览器远程访问。

### 14.2 复用原则

优先复用通用画布、标注、图片比较、保存、云端能力接入和成熟本地工具；产品重点定义设计依据、拆件、上下文继承及一致性审核。

完整候选、来源链接及逐项复用判断见[可复用项目](research/reusable-projects.md)。工程选型见 [ADR](adr/0001-minimum-loop-foundation.md)，接口证据见 [Provider 核查](research/provider-feasibility-2026-09-10.md)，实际通过项见[验证报告](validation/minimum-loop-2026-09-10.md)。公开功能声明不能替代本产品验证。

## 15. 验收与立项条件

### 15.1 必验场景

| 场景 | 通过要求 |
| --- | --- |
| 本机启动与项目恢复 | 双击打开本机界面，重复启动不产生多个后台；刷新和重开后恢复资料、选择与优化链 |
| 画布与图片操作 | 搜索创建、连接、撤销和框选可完成；原始比例查看、并排和叠加比较可用；编辑与连线不自动提交云端请求 |
| 不受支持的音频／视频内容 | 普通界面不提供音视频入口；载入含相关节点的旧上游工作流时明确提示不支持，不静默执行、转换、删除或产生费用 |
| 保存中断与迁移 | 中断后保留上一有效项目，迁移目录仍可加载；单张图片缺失不丢失其他资产 |
| 单张非标准姿态原画 | 可得到人工接受的 A-pose 和基础视图，已有设计变化可被发现和处理 |
| 只框选一个部件 | 无 SAM、无 Mask，也能生成、审核并导出参考 |
| 只用文字指定部件 | 能正确确认目标；存在歧义时允许澄清 |
| 框中包含手和腰带 | 云端模型理解要生成的部件，不要求先分割 |
| 被遮挡的部件 | 利用已有依据补全，推测明确可审 |
| 明确要求像素级提取 | 用户插入本地 SAM，得到可修整和导出的遮罩或透明图；无额外云端分割费用 |
| SAM 未配置或失效 | 默认部件生成路径仍完整可用 |
| 对生成结果不满意 | 可直接连接优化节点继续修正，未批准或未经过 AI 检查的候选也可作为输入 |
| 正面满意、背面偏离原画 | 只优化背面，以正面及原画为参考；正面原图保留，不重新生成或替换 |
| 整组视图需要调整 | 用户明确选择整组优化，产生新候选，保留此前整组结果 |
| 多轮优化或分支尝试 | 有效修改要求持续继承，支持从历史候选分支、比较和选用 |
| 修改与保留视图冲突 | 说明冲突，由用户决定是否扩大范围，不自动重生成其他视图 |
| 连续处理不同部件 | 共享原画和共同约束，各部件的候选及纠错历史独立 |
| 已有背面与非对称设计 | 实际使用设计依据，保持左右和数量 |
| 多张原画冲突 | 用户可明确处理冲突，不自动混合成新设计 |
| 上游修改、重跑和重开 | 保留历史选择，关联结果待复核，无关结果不重跑 |
| 授权失效或请求状态未知 | 可恢复或明确回退，不自动重复消费 |
| 混合 Provider 与替换 | 同一工作流不同节点可用不同 Provider；替换兼容 Provider 不重搭流程，已有选择保留 |
| 能力不兼容 | 多参考输入或严格 Mask 编辑不受支持时说明缺口，不静默降级或丢弃资料 |
| 主 Provider 额度不足 | 提供可用备用选项；未授权新增 API 费用时不自动付费，有授权时遵守范围和预算 |
| 本地工具资源不足 | 提示资源问题，可降规模、手工处理或导入结果，不转交收费云工具；无关生成结果保留 |
| 基础本地图像处理与断网 | 已保存图片可裁切、标注、比较、排版及导出；已安装的离线工具可运行 |
| 检查漏报或误报 | 用户可修正判断，检查不代替最终审核 |
| 工作流预设与分支 | 单部件预设无 Mask 可用，载入不自动生成；复用参考保留用途；修改预设和分支不覆盖已有候选 |
| 资源归属与清单 | 能从图片定位角色、部件、视角、生成及优化来源，迁移后关系保持，导出与所选版本一致 |
| 节点状态与备用记录 | 完成、警告、待复核、选定与批准不混用；发生备用时可追溯原入口、实际入口和切换原因 |
| 默认参考包导出 | 没有 Mask 仍可完整交付，来源和审核状态齐全 |

### 15.2 成功判断

验收采用真实角色资料，覆盖从首次生成、连续优化到最终选择的完整过程，由模型师判断能否继续工作，不能只挑选展示效果好的样图。

- 模型师可将选定部件多角度图交给外部 3D 生成工具或用于人工建模，不必重复解释角色设计。
- 同等输入与交付要求下，人工整理、纠错及交接耗时降低；模型等待时间单列。
- 正式输出均有身份、来源和审核状态。
- 不存在未知的自动付费回退或重复提交。
- 固定代表性任务中，记录各 Provider 的理解、生成和编辑覆盖、成功率、等待及实际成本，确认所选组合符合个人日常使用预期；不设 OAuth 调用占比门槛。
- 将返工、等待和补充费用纳入评价。
- 以获得满意参考所需的总操作负担和总成本判断价值，不以单次生成通过作为必要条件。

### 15.3 立项验证

立项前用实际账号验证至少一套能闭合主流程的 Provider 组合，包括设计理解、参考生成、多参考输入、必要编辑与一致性检查，并记录日常额度、使用条件、耗时和总成本。订阅／OAuth 路径须单独实测，不能用 API 成功冒充订阅可用；若不可用，可在用户认可成本后采用已验证 API 组合，不直接否定产品方向。

Provider 替换与混用需要第二个兼容入口的实测证据；仅验证单一入口时，不宣称已证明可替换性。没有可接受的质量、稳定性或费用组合才构成立项阻塞。未验证入口继续列为候选。

本地基础工具验证完整操作与导出路径。SAM 在用户实际机器上记录模型版本、显存、分辨率、运行耗时、遮罩质量和失败恢复，验证无付费云依赖。SAM 不作为默认生成主流程的立项前提；若未达到要求，应明确精确提取能力尚未通过验收，保留手工或外部遮罩导入路径。

本 PRD 不确定代码、框架、接口、存储、目录结构或开发排期。
